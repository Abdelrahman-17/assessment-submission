# Task 1 — Advanced Network Log Analyzer

## Overview

A Python CLI tool that parses network syslog files, normalizes operational events, detects network risks, stores the complete dataset in SQLite, and exports CSV reports.

The analyzer covers:

- Interface flapping
- BGP session instability
- Frequent BGP down events per device/day
- CPU spikes and critical CPU events
- Repeated SNMP authentication failures
- Thermal alarm recovery duration
- Event classification and normalized fields
- SQLite persistence
- CSV risk reporting
- CLI filtering
- Optional matplotlib visualizations

## Requirements

- Python 3.10+
- matplotlib

Install dependencies:

```bash
python3 -m pip install -r requirements.txt
```

## Run

From the task directory:

```bash
python3 analyzer.py
```

The application:

1. Reads all `.log` files from `logs/`.
2. Parses and normalizes events.
3. Runs the risk detection engine.
4. Stores the complete parsed dataset and risks in SQLite.
5. Generates CSV reports under `output/`.
6. Generates the two optional charts under `output/`.

## CLI Filters

Filter by device:

```bash
python3 analyzer.py --device R1
```

Filter by severity:

```bash
python3 analyzer.py --severity ERROR
```

Filter by category:

```bash
python3 analyzer.py --category Interface
```

Filter by risk level:

```bash
python3 analyzer.py --risk-level Critical
```

Filter by date:

```bash
python3 analyzer.py --date 2025-10-18
```

Filters affect the generated CSV/chart view. The SQLite database always keeps the complete normalized dataset from the full log set.

Filters can also be combined:

```bash
python3 analyzer.py --device R1 --category BGP
```

## Normalized Event Fields

Each parsed event contains:

- `timestamp`
- `device`
- `severity`
- `message`
- `category`
- `interface`
- `interface_state`
- `bgp_neighbor`
- `bgp_state`
- `src_ip`
- `numeric_val`
- `thermal_sensor`
- `thermal_state`
- `source_file`
- `line_number`

## Risk Rules

### Interface Flapping

A flap is counted only when the same device/interface has:

```text
DOWN → UP
```

within 5 minutes.

A Medium-risk finding is generated when at least two such flaps occur within a one-hour rolling window.

### BGP Instability

A High-risk finding is generated when:

- A BGP neighbor transitions from Established to Down within 10 minutes, or
- The same device has more than two BGP down events during one calendar day.

### CPU

- Any CPU value of `95%` or higher is Critical.
- More than two CPU spikes above `80%` within one hour is High.

### SNMP Security

Repeated SNMP authentication failures from the same source IP against the same device are High risk.

### Thermal Recovery

When a temperature threshold-exceeded event is followed by a returned-to-normal event for the same device/sensor, the recovery duration is calculated in minutes.

## Database

SQLite database:

```text
network_events.db
```

Tables:

- `events`
- `risk_summary`

The database is rebuilt from the complete input set on each full analysis run, ensuring deterministic results and a clean schema.

## Assumptions and Limitations

- Input timestamps use `YYYY-MM-DD HH:MM:SS`.
- Timestamps are assumed to use the same timezone.
- The parser is optimized for the supplied Cisco-like sample format.
- Malformed log lines are skipped rather than terminating the whole run.
- Thermal recovery requires a matching threshold-exceeded and returned-to-normal sequence for the same device/sensor.
- CLI filtering does not modify the complete SQLite dataset.
